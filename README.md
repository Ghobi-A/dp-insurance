# Differential Privacy in Machine Learning — a multi-task insurance benchmark

## 1. Project question

**How much utility, calibration and fairness do you give up when you train
models under differential privacy — measured honestly, on tasks that are not
rigged to be easy?**

This repository is a privacy-preserving ML benchmark on the public medical
insurance dataset: conventional baselines vs DP-SGD across a privacy-budget
grid, with leakage-safe evaluation, repeated-seed uncertainty, empirical
privacy audits, membership-inference attacks and group-fairness analysis —
all reproduced by CI.

**Publication status:** the PDF in `paper/` is a superseded historical
manuscript, not the current benchmark or a submission-ready paper. See
[`docs/PUBLICATION_STATUS.md`](docs/PUBLICATION_STATUS.md) for the corrected
privacy boundary, completed ladder result, and remaining research requirements.

**30 September publication stage:** the [plan](docs/PUBLICATION_PLAN.md) is
implemented with clipping sensitivity, household-aware ACS preparation,
uncertainty-aware recommendations and fresh-seed confirmation. The
[findings](reports/publication_stage/FINDINGS.md) report 322 new model fits,
including the executed five-state ACS pilot and 20-seed synthetic primary
comparison. An [editable manuscript](paper/proxy_shift_manuscript.md) records
the supported benchmark claim and remaining submission requirements.

**1 October configuration-selection extension:** [sixteen-source literature survey](docs/CONFIGURATION_SELECTION_LITERATURE.md),
[frozen protocol](docs/CONFIGURATION_SELECTION_PROTOCOL.md) and
[executed findings](reports/configuration_selection/FINDINGS.md). The independent
2017 ACS split and representation sensitivity add **840 fits**. Joint search
restores successful recommendations, but source-only joint search matches
shift-aware successful yield. Simultaneous AUC calibration undercovers in a
small imbalanced clustered scenario. These findings support a bounded
replication/negative-result benchmark; novelty and certification are not claimed.

The reported Opacus budget covers DP-SGD on **prepared feature/label records**.
Scaling, categorical vocabularies, and the `high_cost` training-median target
are learned without privacy accounting. Train-only preprocessing prevents
evaluation leakage; it does not establish end-to-end DP for raw insurance
records. Published reports and predictions are not accounted DP releases either.

## 2. Headline findings

**New exploratory study:** [proxy-shift utility recommendations](docs/PROXY_SHIFT_STUDY.md)
implements matched ordinary/clipping-only/DP-SGD training, validation-only
operating-point selection and held-out proxy failures. It runs synthetic controls
and an insurance charge-unavailability stress case end to end. See the protocol
for reproduction, literature overlap and the ACS external-validation requirement.
This is a candidate paper direction, not established novelty.
The [executed pilot findings](reports/proxy_shift/PILOT_FINDINGS.md) show a
clipping-dominated synthetic interaction and substantial abstention/absolute
utility failures; they do not establish a noise-driven mechanism.

All numbers are generated by executable code (`python -m dp.benchmark`,
5 seeds, 95% repeated-seed intervals); see
[`reports/benchmark_report.md`](reports/benchmark_report.md).

1. **The original task was rigged by a proxy feature.** With `charges`
   available, smoker classification reaches 0.993 ROC-AUC. Remove
   `charges` and the best model drops to **0.537 [0.489, 0.584]** — barely
   above chance. Insurance cost was a near-direct proxy for smoking.
2. **The DP-SGD recipe retains high AUC on `high_cost`.** On this task,
   DP-SGD retains ~98% of the best non-private ROC-AUC even at achieved
   ε ≈ 0.49 (0.933 vs 0.953), and ~99% at ε ≈ 2.
3. **Measured fairness varies across privacy-budget recipes.** On the hard smoker task the
   demographic-parity gap grows as the budget loosens (0.06 → 0.21 from
   ε ≈ 0.5 to ε ≈ 6). This is an association, not a noise-only causal effect.
4. **Empirical attacks supplement, never replace, formal accounting.**
   Loss-threshold/LiRA attacks and the one-run auditor bound ε from below;
   a failed attack does not prove the guarantee.

## 4. Main results table

ROC-AUC, mean over 5 seeds with repeated-seed 95% t-intervals
(full metric panel in [`reports/tables/model_comparison.csv`](reports/tables/model_comparison.csv)):

| Model | smoker_without_charges | high_cost | legacy (with charges) |
| --- | --- | --- | --- |
| Dummy | 0.500 | 0.500 | 0.500 |
| Logistic regression | **0.537 [0.489, 0.584]** | 0.944 [0.927, 0.962] | 0.986 [0.979, 0.994] |
| SVM (RBF) | 0.478 [0.414, 0.542] | 0.947 [0.929, 0.966] | 0.983 [0.972, 0.995] |
| HistGradientBoosting | 0.528 [0.500, 0.557] | **0.953 [0.941, 0.966]** | **0.993 [0.991, 0.994]** |
| Neural (non-private) | 0.536 [0.485, 0.587] | 0.952 [0.936, 0.967] | 0.986 [0.978, 0.995] |
| DP-SGD, ε ≈ 0.49 | 0.486 [0.450, 0.522] | 0.933 [0.909, 0.957] | 0.981 [0.968, 0.994] |
| DP-SGD, ε ≈ 2.0 | 0.525 [0.481, 0.570] | 0.944 [0.927, 0.960] | 0.987 [0.979, 0.994] |
| DP-SGD, ε ≈ 6.0 | 0.536 [0.494, 0.577] | 0.945 [0.928, 0.961] | 0.986 [0.980, 0.993] |

ε values are **achieved** epsilons from the Opacus RDP accountant at
δ = 1e-5, not requested targets. Because tasks can be imbalanced, ROC-AUC /
PR-AUC / macro-F1 are the headline metrics, never accuracy.

The non-private neural baseline uses Adam and early stopping; DP-SGD uses SGD
with a fixed training budget. Their difference includes optimisation and
clipping, so these tables do not isolate the cost of noise alone.

## 5. Architecture

```text
data → dp.tasks (leakage-safe task construction, train/val/test)
     → dp.benchmark (baselines + neural + Opacus DP-SGD, per-seed runs)
     → dp.metrics + dp.fairness (metric panel, group fairness, ECE)
     → dp.uncertainty (tidy results → repeated-seed CIs)
     → dp.reporting (figures, tables, benchmark_report.md)
     ⇄ dp.audit / dp.attacks / dp.canaries (empirical privacy verification)
```

Key invariants: preprocessing fitted on the training partition only;
decision thresholds, early stopping and all tuning use the validation
partition; the test set is touched once per run. Details in
[`docs/EXPERIMENT_DESIGN.md`](docs/EXPERIMENT_DESIGN.md).

## 6. Reproduction

```bash
git clone https://github.com/Ghobi-A/dp-insurance.git && cd dp-insurance
pip install -e ".[experimental,dev]"   # experimental = torch + Opacus for DP-SGD

# full benchmark (all tasks, 5 seeds, ε grid) + reports
python -m dp.benchmark --task all --seeds 0 1 2 3 4 --output-dir reports/generated
python -m dp.reporting --results reports/generated --reports-dir reports

# single task / subset of models
python -m dp.benchmark --task smoker_without_charges \
  --models dummy logistic svm gradient_boosting neural dpsgd \
  --seeds 0 1 2 3 4 --output-dir reports/generated

pytest                 # full suite (privacy regression tests included)
pytest -m "not slow"   # skip expensive DP-SGD integration tests
```

CI reruns linting, the test matrix (3.10–3.12) with coverage, the notebook
end-to-end, and a lightweight benchmark smoke test on every PR; a manual /
scheduled workflow (`full-benchmark.yml`) runs the complete multi-seed grid.

## 7. Privacy auditing

Beyond formal RDP accounting, the project *attacks its own guarantees*
(`src/dp/audit.py`, `attacks.py`, `canaries.py`; analysis in
[`reports/empirical_privacy_report.md`](reports/empirical_privacy_report.md)):

* **One-run auditor** (Steinke, Nasr & Jagielski 2023) — statistical lower
  bounds on ε from membership canaries; wired into the test suite as a
  **privacy regression test** that fails the build when pointed at a
  no-noise implementation (ε ≥ 6.5 vs a claimed ε = 1.0).
* **Membership inference** — loss-threshold and offline/online LiRA, scored
  by TPR at low FPR; the benchmark records loss-threshold AUC for every
  neural/DP-SGD run.
* **Canary constructions** — label-flip, feature-outlier and duplicated
  probes for worst-case auditing.

Three notions stay separate throughout: formal accounting (the guarantee),
empirical lower bounds on ε, and practical attack performance. A
chance-level attack means the attack failed — not that the guarantee is
verified.

## 8. Fairness evaluation

For every task, model and privacy budget the benchmark records demographic
parity difference, equalized odds difference, and per-group TPR / FPR /
sample sizes across `sex`, with repeated-seed intervals and a logged
warning when a group is too small (n < 30) for stable rates. Thresholds are
selected on validation, never test. Curves:
`reports/figures/privacy_fairness_*.png`.

## 9. Methodology corrections

A subsequent methodology audit identified and corrected
sensitivity-accounting, clipping and evaluation-leakage issues in the
original dissertation implementation:

* Feature-noise sensitivity was mis-calibrated (max column range applied
  per column); now the joint sensitivity of the full numeric release under
  one ε.
* Classic Gaussian calibration (invalid for ε > 1) replaced by the analytic
  Gaussian mechanism (Balle & Wang, 2018).
* Clip bounds derived from the private data replaced by fixed public
  domain bounds.
* A fairness threshold tuned on the test set replaced by validation-only
  threshold selection.
* A DP-SGD loop that stepped the unwrapped optimizer (adding no noise) —
  caught by the empirical audit — fixed and guarded by regression tests.

The full audit trail is preserved in
[`reports/findings_report.md`](reports/findings_report.md) and
[`reports/findings_summary.md`](reports/findings_summary.md). In addition,
the original headline task (smoker prediction *with* charges) was found to
be unusually separable; the revised benchmark leads with harder,
leakage-resistant tasks and keeps the original only as a labelled legacy
reference.

## 10. Limitations

* 1,338 rows of a public teaching dataset — not real clinical or actuarial
  evidence ([`docs/DATA_CARD.md`](docs/DATA_CARD.md)).
* Repeated-seed intervals describe pipeline run-to-run variability, not
  independent-sample statistical guarantees.
* Fairness analysis is limited to a binary `sex` attribute.
* On `smoker_without_charges` the remaining features carry little signal;
  conclusions there are about the *gap*, not about a usable classifier.
* Empirical audits on a dataset this small lack the power to certify small
  ε values; "not broken" ≠ "verified".
